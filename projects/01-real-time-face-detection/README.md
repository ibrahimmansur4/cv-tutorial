# Project 1: Real-Time Face Detection

Detect frontal faces from a webcam, image, or video with two OpenCV pipelines:

- a classical Haar cascade; and
- OpenCV's Caffe/SSD face detector through the DNN module.

The Python application draws face boxes, reports throughput, supports camera
and file inputs, and can run without a GUI. The project is deliberately
CPU-friendly and does not require a GPU.

## What the two detectors teach

### Haar cascade

A Haar cascade is a classical, hand-designed computer-vision pipeline. It
converts each frame to grayscale, equalizes its histogram, evaluates contrast
patterns called Haar-like features very quickly with an integral image, and
uses an AdaBoost-trained cascade to reject most non-face windows in early
stages. OpenCV's `detectMultiScale` searches several positions and scales, then
groups overlapping detections.

This detector is small and fast, but it is sensitive to pose, shadows, scale,
and the `scaleFactor`, `minNeighbors`, and minimum-face-size settings. It does
not provide a calibrated confidence score, so its boxes are shown without one.

### DNN face detector

The DNN option loads OpenCV's ResNet-10 SSD face detector. Each BGR frame is
resized into a `300 x 300` blob, mean values are subtracted, and one forward
pass predicts normalized boxes and confidence scores. Predictions below the
selected threshold are removed and the remaining boxes are clipped to the
frame.

The learned model is generally more tolerant of pose and lighting than the
Haar cascade, but it costs more CPU time and requires separate configuration
and weight files. The confidence value ranks model predictions; it is not the
probability that the identified person is someone in particular. This project
detects faces only--it does not recognize identities.

## Pipeline and code boundaries

```text
camera / image / video
          |
          v
capture and input validation       application logic
          |
          v
grayscale + image pyramid          computer vision (Haar)
             OR
blob + neural-network inference    CV preprocessing + ML model (DNN)
          |
          v
threshold, clip, annotate          computer vision
          |
          v
FPS, display, file writer          application logic
```

The implementation preserves those boundaries rather than putting everything
in one loop:

- **Detector code** owns model loading and turns a frame into face detections.
- **Vision/visualization code** prepares pixels, clips boxes, and draws labels.
- **Application code** parses arguments, opens the source and output, handles
  end-of-stream and keyboard input, and measures FPS.

Start at `python/face_detection.py`; supporting modules live beside it.

## Requirements

- Python 3.10 or newer (tested with Python 3.12)
- A webcam for live mode; image and video modes work without one

From the repository root:

```powershell
cd projects/01-real-time-face-detection
```

## Model setup

Haar mode can use the cascade bundled with `opencv-python`. DNN mode needs a
configuration and weight file; downloading the cascade as well makes experiment
inputs explicit and reproducible. Download all three files from the official
OpenCV repositories with Python (cross-platform):

```powershell
python scripts/download_models.py
```

On Windows, the equivalent PowerShell script is also available:

```powershell
./scripts/download_models.ps1
```

Both downloaders are idempotent, validate that each download is plausibly
complete, and create:

```text
models/haarcascade_frontalface_default.xml
models/deploy.prototxt
models/res10_300x300_ssd_iter_140000_fp16.caffemodel
```

Use `python scripts/download_models.py --force` (or the PowerShell `-Force`
switch) to replace existing files. Pass `--destination` in Python or
`-Destination` in PowerShell to stage them elsewhere. The downloaders use only the official
[`opencv/opencv`](https://github.com/opencv/opencv) and
[`opencv/opencv_3rdparty`](https://github.com/opencv/opencv_3rdparty)
repositories.

## Run the Python implementation

Run these commands from `projects/01-real-time-face-detection`.

Haar with the default webcam:

```powershell
python python/face_detection.py --detector haar --camera 0 --resolution 640x480
```

Pass the downloaded cascade explicitly for a fully reproducible comparison:

```powershell
python python/face_detection.py --detector haar --camera 0 `
  --cascade models/haarcascade_frontalface_default.xml
```

DNN with confidence labels:

```powershell
python python/face_detection.py --detector dnn --camera 0 --confidence 0.5 `
  --dnn-config models/deploy.prototxt `
  --dnn-model models/res10_300x300_ssd_iter_140000_fp16.caffemodel
```

Headless image input and output:

```powershell
python python/face_detection.py --detector dnn `
  --input assets/input/group.jpg --no-display `
  --output assets/output/group-dnn.jpg `
  --dnn-config models/deploy.prototxt `
  --dnn-model models/res10_300x300_ssd_iter_140000_fp16.caffemodel
```

Reproduce both bundled sample outputs (the DNN command requires model setup):

```powershell
python python/face_detection.py --detector haar `
  --input assets/input/sample-face.png --no-display `
  --output assets/output/sample-face-haar.png

python python/face_detection.py --detector dnn `
  --input assets/input/sample-face.png --no-display `
  --output assets/output/sample-face-dnn.png `
  --dnn-config models/deploy.prototxt `
  --dnn-model models/res10_300x300_ssd_iter_140000_fp16.caffemodel
```

Headless video benchmark with a bounded run:

```powershell
python python/face_detection.py --detector haar `
  --input assets/input/people.mp4 --no-display --max-frames 300 `
  --output assets/output/people-haar.avi
```

Use `python python/face_detection.py --help` for every option. `--input`
selects an image or video and takes precedence over the default camera source.
`--max-frames 0` (the default) means no artificial frame limit. When no
`--input` is supplied, `--resolution` requests the capture size from the camera;
a camera driver may return a nearby supported size instead.

Run the unit tests without a camera:

```powershell
python -m unittest discover -s python/tests -v
```

## Inputs, controls, and outputs

- **Webcam:** camera index `0` is usually the built-in camera. Try `1` if an
  external or virtual camera is first in the operating system's list.
- **Image:** pass a readable image to `--input` and an image filename to
  `--output`, for example `assets/output/group-dnn.jpg`.
- **Video:** pass a readable video to `--input`. `.avi` is the most portable
  output choice; the application uses MJPG for `.avi` and MPEG-4 Part 2 for
  `.mp4`, `.mov`, and `.mkv`.
- **Interactive mode:** press `q` or `Esc` to stop a webcam/video run. An image
  stays open until a key is pressed.
- **Headless mode:** use `--no-display`. Add `--output` when annotated media is
  required; omit it for a pure throughput run.

The program overlays a responsive 30-frame rolling detector-processing FPS.
DNN detections also show confidence. At shutdown, the console summary reports
the processed frame count, total detections, and detector-processing throughput
averaged over the complete run. No output file is written unless `--output` is
supplied. Input and output paths must differ so source media cannot be
overwritten accidentally.

The repository includes one synthetic, fictional portrait so a positive
detection can be reproduced without storing a real person's camera frame or
depending on third-party image licensing. Both detectors find one face in the
sample. The displayed FPS values come from a single still-image run and are not
benchmark results. See `assets/README.md` for provenance and the generation
prompt.

| Input | Haar output | DNN output |
|---|---|---|
| [Synthetic portrait](assets/input/sample-face.png) | [Haar detection](assets/output/sample-face-haar.png) | [DNN detection](assets/output/sample-face-dnn.png) |

under `assets/output/`, remain ignored so large or unlicensed media is not

## Reproducible Haar-versus-DNN experiment

Use a recorded video for the primary comparison. A single file gives both
detectors exactly the same frames and removes variation caused by webcam
exposure timing.

1. Record or select clips containing the same people at bright, normal, dim,
   and backlit conditions. Include frontal, turned, partly occluded, near, and
   small/distant faces. Obtain consent from anyone recorded.
2. Fix the input resolution, machine power mode, OpenCV version, and all CLI
   settings. Close unrelated CPU-heavy applications.
3. Run one warm-up pass, then at least three measured passes per detector.
   Prefer `--no-display` and no output writer for compute-only FPS; display and
   encoding otherwise become part of the benchmark.
4. For detection quality, label a representative frame sample. Count a
   detection as a true positive when its intersection-over-union (IoU) with a
   ground-truth face is at least `0.5`. Report precision, recall, false
   positives, and false negatives rather than the ambiguous word "accuracy."
5. Record process CPU usage after warm-up with the same operating-system tool
   for every run (Task Manager, Performance Monitor, `top`, or `pidstat`). Note
   whether the value is per-core or normalized over all cores.
6. Repeat by lighting condition. Change only one setting at a time, such as DNN
   confidence or input resolution, and save annotated examples of successes and
   failures.

Suggested results table:

| Detector | Lighting | Resolution | Settings | Precision | Recall | Mean FPS | Mean CPU | Notes |
|---|---|---:|---|---:|---:|---:|---:|---|
| Haar | normal | 640x480 | defaults | | | | | |
| DNN | normal | 640x480 | confidence=0.5 | | | | | |

Keep raw observations under `results/` and annotated evidence under
`assets/output/`. Include the OpenCV version, CPU model, operating system,
run count, and whether rendering/encoding was enabled alongside any published
numbers.

## Error handling and troubleshooting

The application validates arguments and fails with a non-zero exit status and
a useful message instead of silently continuing.

- **Camera cannot be opened:** close other camera applications, grant camera
  permission, and try another `--camera` index.
- **Input cannot be read:** check the path and codec support. Test a `.jpg` or
  MJPG `.avi` when a platform-specific video codec fails.
- **Cascade/model/config cannot be loaded:** run the download script, launch
  from the Project 1 directory, or pass explicit absolute paths.
- **DNN model/config mismatch:** use the `deploy.prototxt` and FP16 Caffe model
  downloaded together by this project's script.
- **Output writer cannot open:** create the parent directory, choose `.avi`,
  and verify that the location is writable.
- **Input and output paths match:** choose a different output filename; the
  application refuses to overwrite its source image or video.
- **No GUI/display is available:** add `--no-display`. A GUI-enabled OpenCV
  package and desktop session are required for an interactive window.
- **Low or unstable FPS:** disable output encoding, reduce the capture
  resolution, and let camera auto-exposure settle before measuring.
- **No faces detected:** begin with a well-lit frontal face, verify that the
  image is not extremely small, then lower DNN confidence cautiously or tune
  the Haar parameters.

## Limitations and next steps

- The supplied Haar cascade is primarily a frontal-face detector and degrades
  under strong rotation, occlusion, blur, and uneven illumination.
- The compact SSD model can miss very small faces and may produce biased error
  rates across demographics or capture conditions. Evaluate it on data that
  represents the intended use.
- FPS is hardware-, backend-, resolution-, display-, and codec-dependent; do
  not compare numbers collected with different settings as if they were equal.
- Frame-by-frame detection can flicker and repeats work. Tracking detections
  between periodic inference passes can improve stability and throughput.
- Possible upgrades include YuNet or another ONNX detector, non-maximum
  suppression tuning, stronger illumination normalization, DNN backend/target
  selection, batched evaluation, and a labeled test set with automated metrics.
- Face detection has privacy implications. Avoid covert capture, disclose
  recording, minimize retention, and do not treat detection as identity,
  emotion, intent, or demographic inference.
